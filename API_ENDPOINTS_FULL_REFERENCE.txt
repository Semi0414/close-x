C) LISTING APIs (Protected)
============================================================

C1. GET /listings
URL: {{base_url}}/listings
Query params (supported):
- Flat: ?city=Dubai&status=for sale&listing_type=sale&off_plan=true&property_type=Apartment&beds=3&min_price=1200000&max_price=8000000&tags=urgent,below market&keyword=dubai&page=1
- Nested (mobile): ?filters[city]=Dubai&filters[status]=for sale  OR  ?filters={"city":"Dubai","status":"for sale"}
- status / listing_type (sale, rent, requirement, for sale, for rent, buy request, etc.)
- off_plan / is_off_plan (true/false or 1/0) — omit when not filtering
- city, area, property_type (partial match on column + form_data)
- beds (exact, or min when from filter UI), min_beds (>=), baths
- min_price, max_price (uses listings.price or form_data price-sp)
- tags (comma separated; ANY tag match)
- keyword, q, search
- page
Body: none
Empty results: { "message": "No listings found for the selected filters.", "listings": [], "pagination": {...} }
Response always includes "applied_filters": {} showing what the server received (debug Apply button).
GET or POST /listings both accepted; filters may be query, JSON body, or filters={...}.

C2. GET /listings/search
URL: {{base_url}}/listings/search
Same filters/pagination as /listings
When no results: includes message "No listings found matching your search." (or "No listings found." if keyword empty)
Keyword also accepts compact prices (parsed from the search string):
  12k, 22M, 1.2M, 12k AED, 22M USD, $22M, AED 12M (currency after amount)
  Matches listings.price (and price in form_data) by rounded thousands/millions; optional currency filter (AED, USD, EUR, GBP, $).
  Examples: ?keyword=12M+AED  ?keyword=downtown+Dubai  ?keyword=12k+downtown
  Mixed keyword: location text OR price match (broad search).

C3. GET /listings/my

C5. GET /listings/filters

L) QUICK POSTMAN CHECKLIST
============================================================

1) For protected APIs always add Bearer token.
2) Use valid JSON (double quotes, key:value syntax), not key=value inside JSON object.
3) For file endpoints, switch to form-data.
4) For saved searches, recommended filters payload:
{
  "status": "for sale",
  "off_plan": true,
  "city": "Dubai",
  "property_type": "apartment",
  "beds": 3,
  "min_price": 1200000,
  "max_price": 8000000,
  "tags": ["urgent", "below market"],
  "keyword": "dubai"
}
